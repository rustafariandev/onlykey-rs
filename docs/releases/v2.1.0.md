# okagent 2.1.0: Windows support

okagent 2.1.0 runs on Windows. Your OnlyKey now serves SSH keys to Windows'
OpenSSH, PuTTY and Git for Windows, and it installs from an MSI with no
administrator rights.

Linux and macOS users get the same agent as 2.0.0, with no configuration
changes needed.

## What's new

okagent now works with every common SSH client on Windows.

| Client | How okagent reaches it |
| --- | --- |
| Windows' OpenSSH (`ssh`, `ssh-add`, `scp`) | A named pipe, `\\.\pipe\okagent-USER`, found through `SSH_AUTH_SOCK` |
| PuTTY, Plink, WinSCP, FileZilla, TortoiseGit | `serve --pageant` (or `pageant = true`) answers on Pageant's pipe and window |
| Git Bash, MSYS2, Cygwin | A Cygwin-style socket at `%LOCALAPPDATA%\okagent\agent.sock`, readable only by you |
| Git from PowerShell or cmd | `okagent run` and `okagent shell` point `GIT_SSH` at Windows' OpenSSH |

- **Background agent.** `okagent serve --daemon` starts a detached agent and
  prints PowerShell for `Invoke-Expression`. From Git Bash it prints sh for
  `eval` instead.
- **Windows conventions.** The config lives at
  `%APPDATA%\okagent\config.toml`, and `okagent shell` starts `%COMSPEC%`
  (Git Bash's shell from Git Bash).
  Challenge digits and `ssh-add -c` confirmations show in the agent's console.
- **Your keys.** OnlyKey keys, derived or stored, need nothing special on
  Windows.

## Install

Download the MSI or the zip from the
[v2.1.0 release](https://github.com/rustafariandev/onlykey-rs/releases/tag/v2.1.0).
Both install for the current user only, to
`%LOCALAPPDATA%\Programs\okagent`, and need no administrator rights. The C
runtime is linked statically, so no Visual C++ redistributable is needed.

**MSI** (`okagent-2.1.0-x86_64-pc-windows-msvc.msi`). It adds okagent to your
`PATH`, sets `SSH_AUTH_SOCK` to the agent's pipe, starts the agent, and starts
it again at every logon.

- `msiexec /i okagent-2.1.0-x86_64-pc-windows-msvc.msi AUTOSTART=0` installs
  without autostart.
- `AUTHSOCK=0` leaves `SSH_AUTH_SOCK` alone.
- To upgrade, install a newer MSI. It remembers both settings and stops the
  running agent first.
- To uninstall, use Settings → Apps.

**Zip** (`okagent-2.1.0-x86_64-pc-windows-msvc.zip`), for installing without
Windows Installer. From the unzipped folder:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -Autostart
```

Run it again from a newer zip to upgrade. `-NoAuthSock` leaves
`SSH_AUTH_SOCK` alone, and `install.ps1 -Uninstall` removes everything.

Linux and macOS packages (static binary, .deb, .rpm, Arch) ship as before,
with a `SHA256SUMS` file and build provenance attestations.

## Getting started

After the MSI, the agent is already running, and new shells find it through
`SSH_AUTH_SOCK`. To start one by hand in PowerShell:

```powershell
okagent serve --daemon | Invoke-Expression   # sets $env:SSH_AUTH_SOCK and $env:SSH_AGENT_PID
ssh-add -L
```

In Git Bash:

```sh
eval "$(okagent serve --daemon)"
ssh-add -L
```

For PuTTY, quit Pageant first, then turn on Pageant support in
`%APPDATA%\okagent\config.toml` and restart the agent:

```toml
pageant = true

[[identity]]
name = "ferris@example.com"
```

`okagent pubkey ferris@example.com` prints the line for the server's
`authorized_keys`. PuTTY asks Pageant for keys by default, so leave its
private key file empty.

On each login, press the button the OnlyKey lights up. The agent started at
logon has no console, so add `notify-command` to the config to see the
challenge digits.

A few things to know:

- Windows' own `ssh-agent` service is separate from okagent and can stay
  stopped.
- Git for Windows runs its bundled `ssh`, even from PowerShell. Under
  `okagent serve`, point Git at Windows' OpenSSH once:
  `git config --global core.sshCommand C:/Windows/System32/OpenSSH/ssh.exe`.
- FIDO security keys (`sk-` keys) need an elevated agent, because Windows
  only lets administrator processes open a FIDO authenticator directly.
  Without elevation the key is hidden entirely, so the error asks whether
  you are running as administrator. The OnlyKey's own FIDO interface works
  too, and is used on its own when no other security key is attached.

## Upgrading on Linux and macOS

2.1.0 is a drop-in upgrade: no commands, flags or config settings were
removed or changed.

- With no other FIDO security key attached, `sk-` keys and `load-resident`
  use the OnlyKey's own FIDO interface. `--fido-device` is no longer needed
  for that.
- USB traffic to the OnlyKey is unchanged. hidapi drops the new leading
  report ID byte there, which Windows needs.
- The `onlykey-agent` library only gains APIs, so code built against 2.0.0
  still compiles.
- okagent now uses ssh-agent-kit 1.2.0 from crates.io.
